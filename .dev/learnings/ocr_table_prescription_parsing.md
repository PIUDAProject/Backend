# 표 형태 처방전 OCR 파싱 한계

## 현상
Naver CLOVA OCR이 표 처방전을 인식하면 텍스트 순서가 아래처럼 나온다:

```
처방의약품의 명칭
1회 투약량
1일 투여횟수
총 투약일수
용 법
4
4
4
3
3
2
3
3
2
[급여][643501510]써스펜8시간이알서방정650밀
...
```

컬럼 헤더 → 숫자 전체(모든 약의 값이 묶여서) → 약 이름 순으로 나열됨.
약 이름과 수치가 텍스트 순서상 멀리 떨어져 있어서 정규식으로 매칭 불가.

## 원인
OCR은 공간 좌표가 아니라 텍스트 흐름(reading order)으로 결과를 반환한다.
표의 경우 컬럼별로 묶어서 읽는 경향이 있어서 행(row) 단위 구조가 사라진다.

## 현재 처리 방식 (3-2 기준)
- 약 이름 정규식은 잘 동작 (약 이름은 `[급여]` 코드 패턴으로 비교적 명확)
- timesPerDay, totalDays는 null로 반환
- rawText를 응답에 포함하므로 클라이언트에서 사용자 직접 입력 가능

## 개선 방향 (3-3 이후 백로그)
boundingPoly(각 텍스트 블록의 x, y 좌표)로 같은 y좌표 범위에 있는 텍스트를 같은 행으로 클러스터링.

```
행 1: "써스펜8시간이알서방정" (y≈200) | "1" (y≈200) | "3" (y≈200) | "4" (y≈200)
행 2: "맥시부펜이알정" (y≈240) | "1" (y≈240) | "3" (y≈240) | "4" (y≈240)
```

필요 작업:
- NaverOcrApiResponse에 boundingPoly 필드 추가
- y좌표 클러스터링 로직 (허용 오차 ±10px 내 같은 행으로 판단)
- OcrParser가 List<ParsedOcrData> 반환하도록 구조 변경
- 3-3의 "여러 약 한번에 등록" 기능과 자연스럽게 묶임
